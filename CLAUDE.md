# Coin (iOS) — правила кодирования

## Организация файлов

- **Один независимый объект — один файл.** Каждый `struct`/`class`/`enum`, представляющий самостоятельную модель (Model/, Repository/Model/, Network/Model/, включая мелкие Req/Res-структуры под один эндпоинт), — в своём файле `<TypeName>.swift`.
- **Каждая View — в своём файле.** Включая мелкие вспомогательные subview, которые раньше жили как private struct внутри родительского файла.
- **Каждая ViewModel — в своём файле.**
- Файл называется точно как объявленный в нём тип: `AccountType.swift` содержит `enum AccountType`.
- Если в файле одна декларация совпадает по имени с файлом, а остальные — вспомогательные (например, `Route`-enum рядом с экраном) — выносим вспомогательные в отдельные файлы, основную оставляем в файле с оригинальным именем.

### Исключения (не разбивать)

- Файлы, целиком состоящие из `extension` на чужие типы (например, `Network/ProtoExtensions.swift` — extensions на сгенерированные proto-типы, бриджинг-инициализаторы). Держим их одним файлом.
- Свободные функции/константы уровня файла (не struct/class/enum) можно оставлять как есть.

### Важно при переносе типа в новый файл

- Если тип или используемая им `let`/`func` были `private`/`fileprivate` из-за совместного нахождения в одном файле с вызывающим кодом — при разнесении по файлам это сломает компиляцию. Нужно либо снять модификатор (сделать `internal`), либо завести отдельную copy-константу (например, свой `private let logger` в каждом новом файле по паттерну, уже принятому в проекте — `Logger(subsystem: "Coin", category: "<Имя файла/фичи>")`).

## Xcode-проект (важно!)

Проект **не использует** file-system-synchronized groups (нет `PBXFileSystemSynchronizedRootGroup` в `project.pbxproj`) — старый формат с явными ссылками на файлы. Это значит:

- Просто создать `.swift`-файл на диске **недостаточно** — Xcode не увидит его и не скомпилирует, пока он не добавлен в `project.pbxproj` (`PBXFileReference` + `PBXBuildFile` в `Sources`-фазе + помещён в нужную `PBXGroup`) для нужных таргетов (`Coin`, `CoinDev`).
- Регистрировать файлы в `project.pbxproj` — **только через `xcodeproj` Ruby gem** (`gem list -i xcodeproj` → уже установлен, ruby по `/usr/bin/ruby`). Никогда не редактировать `project.pbxproj` вручную через sed/regex — легко повредить формат.
- После любого разнесения/переименования файлов — обязательная сборка (`xcodebuild -scheme CoinDev -destination "id=69950084-50EC-4E4C-9EBD-DE8C3FDC9379" build`) для проверки, что регистрация файлов прошла верно.
